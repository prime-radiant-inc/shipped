## Featured

<article class="repo">

### [obra/superpowers](https://github.com/obra/superpowers)

<p class="repo-desc">An agentic skills framework and software-development methodology that works.</p>

<RepoStat org="obra" name="superpowers" week="2026-06-29" />

Two releases this week — `v6.1.0` and `v6.1.1` — and the throughline is Codex. `v6.1.0` shipped Codex marketplace install support, a leaner per-session bootstrap, and removed the Gemini CLI path; `v6.1.1` followed with a run of Codex-hook correctness fixes: repairing `SessionStart` hook re-registration, adding Codex portal packaging, fixing the plugin manifest category, and suppressing hook auto-discovery when the hooks object is empty. There's a smaller editorial thread in here too — trimming per-harness tool-mapping boilerplate and compressing the bootstrap prose so the skills cost less context to load — but the week's real story is making superpowers a first-class citizen on Codex.

</article>

<article class="repo">

### [obra/insanitty](https://github.com/obra/insanitty)

<p class="repo-desc">Native Linux (GTK4 / libadwaita) terminal workspace manager — a port of Fantastty, built on embedded Ghostty with tmux-backed workspaces and a QUIC remote engine.</p>

<RepoStat org="obra" name="insanitty" week="2026-06-29" />

New this week, and it arrived at a sprint. In a single week the project went from an empty repo to a working native-Linux terminal workspace manager: a Swift/GTK4 app skeleton around an embedded Ghostty terminal, with a tmux control-mode protocol as the foundation. The user-facing features landed in the same window — splits, tabs, browser tabs, layout and session persistence across restart, workspace rename/archive/trash, drag-to-reorder — alongside a native Swift QUIC client and a ported remote-grid protocol that renders a remote workspace right in the GUI, interop-tested against the real helper. Packaging and CI stood up in parallel: Swift-toolchain CI, `.tar.gz` and `.rpm` targets, an MIT license matched to Fantastty, and end-to-end regression screenshots refreshed as each piece landed.

</article>

<article class="repo">

### [prime-radiant-inc/agent-plugin-linear-use](https://github.com/prime-radiant-inc/agent-plugin-linear-use)

<p class="repo-desc">Keep AI-driven work tracked in Linear: a Claude Code / Codex skill + hook that finds or creates a ticket and moves it through your workflow.</p>

<RepoStat org="prime-radiant-inc" name="agent-plugin-linear-use" week="2026-06-29" />

New and public on purpose. The initial release is the linear-use plugin itself — a skill plus a hook that automatically finds or creates a Linear ticket for the work an agent is doing and moves it through its workflow states, so AI-driven work stays tracked without a human minding the board. A same-week adversarial-review pass tightened the first cut, and a small fix corrected the commit author email — attribution matters on a repo we publish as a worked example of how we run Prime Radiant.

</article>

## Also shipped

<article class="repo">

### [prime-radiant-inc/serf](https://github.com/prime-radiant-inc/serf)

<p class="repo-desc">A non-interactive coding agent: give it a prompt and it reads, writes, runs commands, and searches code in a loop until the work is done, using native tool-calling across OpenAI, Anthropic, and Google models.</p>

<RepoStat org="prime-radiant-inc" name="serf" week="2026-06-29" />

The busiest repo of the week by commit volume, and the work was mostly serf turning its tools on itself. The throughline — captured in the one merged PR, "corpus refresh + coverage-floor ratchet" — is a multi-phase hardening campaign: schema-aware fuzzing of tool arguments, a failure-to-regression promoter that turns each new crash into a permanent test, real-traffic corpus harvesting, and coverage-floor ratchets applied module by module across the llm, auth, agent, hub, and TUI packages. A second, real thread is TUI and web polish — a provider-grouped, prettified, badged model picker, a colorblind-safe status vocabulary that leans on distinct shapes rather than color alone, an amber→blue recolor for "needs you" states, and the Lucide icon set vendored for one status language across surfaces — plus a settings-UI refactor split into per-concern files and some early self-healing tool-call repair. But the headline is coverage: this was the week serf got serious about not breaking.

</article>

<article class="repo">

### [prime-radiant-inc/teststrip](https://github.com/prime-radiant-inc/teststrip)

<p class="repo-desc">macOS photo-culling app — catalog-first, non-destructive, AI-assisted. Early development; not ready for use.</p>

<RepoStat org="prime-radiant-inc" name="teststrip" week="2026-06-29" />

A project in the thick of early development, and it covered a lot of ground in a week — from foundation to features. The early days laid the plumbing: a Swift package bootstrap, the asset/catalog domain model, a SQLite catalog repository, a decode-and-preview pipeline, and folder-ingest planning. By week's end it was shipping the culling workflow itself: top-ranked stack culling, signal-backed compare recommendations, a compare "keep all," and a compact rapid-cull rationale. A people/face-review workflow arrived too — manual review actions, naming selected photos, persisting confirmed people groups — and Smart Collections became contextual and actionable with a suggestion engine, preset composition, and typed rules. Throughout, the "alpha plan" doc got refreshed after nearly every slice. Not ready for use yet, but moving fast.

</article>

### [prime-radiant-inc/llm-proxy](https://github.com/prime-radiant-inc/llm-proxy)
