The first week we're recapping opens with a release we'd been building toward: **serf** shipped its `v0.1.0` — during its single busiest week of the window. And it's one of a spread of repos active across `prime-radiant-inc` and `obra`, from a brand-new Go workflow orchestrator to a sweeping reshaping of how the eval lab handles model credentials.

## Featured

<article class="repo">

### [prime-radiant-inc/serf](https://github.com/prime-radiant-inc/serf)

<p class="repo-desc">A non-interactive coding agent: give it a prompt and it reads, writes, runs commands, and searches code in a loop until the work is done — native tool-calling across OpenAI, Anthropic, and Google models.</p>

<RepoStat org="prime-radiant-inc" name="serf" week="2026-06-22" />

serf cut two releases on June 22 — a `snapshot` prerelease and then its first real tagged release, `v0.1.0` — and it did so during the busiest week of any repo here. Three changes landed via merged PRs: a substantial (~58%) speed-up to `NewSession` by memoizing the per-session git/schema/uname work, an ATIF-v1.7 conformance fix so orphaned tool results stay valid, and a maintainability cleanup pass (shared helpers, table-driven tests, file splits). This is the agent that does the work when nobody's watching — and it's now something you can pin a version of.

</article>

<article class="repo">

### [prime-radiant-inc/toil](https://github.com/prime-radiant-inc/toil)

<p class="repo-desc">A file-defined workflow orchestrator in Go — YAML workflows and runners, disk-persisted state, resume, approvals, and live graph views.</p>

<RepoStat org="prime-radiant-inc" name="toil" week="2026-06-22" />

New this week. The initial public release landed the whole project at once, followed by a rewrite of `toil help` in the "tgwm" style — grouped by audience rather than by flag. toil is the piece that turns a pile of steps into a durable, resumable workflow with approvals and a live view of the graph as it runs.

</article>

<article class="repo">

### [obra/temp-sp-codex](https://github.com/obra/temp-sp-codex)

<p class="repo-desc">A temporary test repo for the Superpowers Codex marketplace.</p>

<RepoStat org="obra" name="temp-sp-codex" week="2026-06-22" />

New this week, and honest about what it is: a throwaway test bed for the Codex marketplace manifest work happening over in superpowers. It added the Codex marketplace manifest and kept the Codex hooks manifest in plugin metadata. It earns a mention because it was created in-window, not because it's a product.

</article>

## Also shipped

<article class="repo">

### [prime-radiant-inc/superpowers-evals](https://github.com/prime-radiant-inc/superpowers-evals)

<p class="repo-desc">The Quorum behavioral eval lab — drives real coding-agent CLIs (Claude, Codex, Gemini, Kimi, and more) through a QA agent and grades them on workflow compliance.</p>

<RepoStat org="prime-radiant-inc" name="superpowers-evals" week="2026-06-22" />

One of the busiest repos of the week, and almost all of it is a single coherent thread — the "credential axis." The lab learned to describe every model endpoint in a `credentials.yaml` with a `default_credential`, thread that credential through runs, verdicts, and dashboards, and build per-harness provider config (pi, opencode, codex, claude, gemini) from it. Alongside that: a new serf coding-agent harness, per-endpoint concurrency caps keyed on a `limiterKey`, scenario-local fixtures, and a user-preference-override eval suite.

</article>

<article class="repo">

### [prime-radiant-inc/llm-proxy](https://github.com/prime-radiant-inc/llm-proxy)

<p class="repo-desc">A transparent logging proxy for LLM API traffic — auto-configures clients and records every request and response for debugging, auditing, and analysis.</p>

<RepoStat org="prime-radiant-inc" name="llm-proxy" week="2026-06-22" />

A single theme this week: run attribution. The proxy gained a neutral "run attribution envelope" (parser plus metadata), then routing to carry it through generic providers, Bedrock, and mantle traffic — so every logged request can be traced back to the run that made it. Plus a fix to preserve the configured log directory.

</article>

<article class="repo">

### [prime-radiant-inc/gauntlet](https://github.com/prime-radiant-inc/gauntlet)

<p class="repo-desc">An AI-powered QA framework that drives web apps, CLI tools, and TUI programs from markdown story cards and returns structured pass/fail verdicts with evidence.</p>

<RepoStat org="prime-radiant-inc" name="gauntlet" week="2026-06-22" />

Both changes this week were about authentication: support for Claude subscription OAuth on the Anthropic client, then a fix to pin `apiKey: null` in OAuth mode so the SDK sends only a Bearer token.

</article>
