Two heavyweights defined the week. **gauntlet** landed its v1.5 transition — server-owned runs, a real configuration system, and per-run browser isolation — across sixty-nine commits. **hearthstone** matured on the operations side: an admin console, house deletion with proper `410 Gone` semantics, token-bucket rate limiting, a security pass that stopped leaking owner PINs, and a relicense to Apache 2.0. Elsewhere, a new **kindle-highlight-exporter** turned Kindle annotations into Markdown, and **superpowers** built tooling to mirror itself as a Codex plugin.

## Featured

<article class="repo">

### [prime-radiant-inc/gauntlet](https://github.com/prime-radiant-inc/gauntlet)

<p class="repo-desc">An AI-powered QA testing framework.</p>

<RepoStat org="prime-radiant-inc" name="gauntlet" week="2026-04-13" />

Sixty-nine commits drove the v1.5 transition. Runs became server-owned — an `ActiveRunRegistry` tracks in-flight runs, execution detaches behind a `202`, and a fresh WebSocket connection receives a snapshot on open — with the UI rebuilt around URL-driven live runs and run IDs as the primary identity. A real configuration system landed alongside: an `AppConfig` type with precedence and source tracking, a `gauntlet config` subcommand, a `/api/config/effective` inspection endpoint, and loud rejection of unknown CLI flags. v1.5 itself brought a context module, per-run browser isolation, profiles with passkey support, and hardened HTTP/CLI boundary validation. Matt Windbrook drove the week; Simon Willison contributed two commits.

</article>

<article class="repo">

### [prime-radiant-inc/hearthstone](https://github.com/prime-radiant-inc/hearthstone)

<p class="repo-desc">A household knowledge assistant — a retrieval service over your own documents, with an iOS client and a guest-sharing model.</p>

<RepoStat org="prime-radiant-inc" name="hearthstone" week="2026-04-13" />

Seventy commits shifted hearthstone toward operability and safety. A shareable join flow arrived — `join_url`s, a `/join/:pin` landing page, and QR codes that encode them — alongside an admin console (a boot-minted admin token, a `requireAdmin` middleware, and an admin UI) for managing houses. House deletion was built out carefully: cascade deletes, `410 Gone` for removed houses (which the app detects and prunes from its sidebar), and a last-owner guard. A token-bucket rate limiter landed with tiered limits, Fly/XFF client-IP resolution, and an admin panel for live throttles. A security pass scrubbed placeholder emails from API responses and stopped leaking owner PINs to an external QR-code service by rendering QR codes server-side. And the project relicensed to Apache 2.0. Sole contributor: Matt Windbrook.

</article>
