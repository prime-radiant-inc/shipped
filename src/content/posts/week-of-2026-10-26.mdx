## Featured

<article class="repo">

### [prime-radiant-inc/streamlinear](https://github.com/prime-radiant-inc/streamlinear)

<p class="repo-desc">A lightweight Linear MCP server for Claude Code that exposes one tool with action dispatch (search, get, update, comment, create, graphql, help) using ~500 tokens instead of the standard MCP's ~17,000.</p>

<RepoStat org="prime-radiant-inc" name="streamlinear" week="2026-10-26" />

Two tagged releases, both with hand-written notes. **v1.2.0**: labels wired into `create`/`update` (names resolve against the workspace label list, clearing the list on update, and an unknown label errors out listing the available options), `state` and UUID-based `assignee` support on `create`/`update`, a new `STREAMLINEAR_POST_ONLY` mode that disables `search`/`get`/`graphql` so an agent can create and update issues without ever reading issue content, `@mention` conversion to Linear profile links when a mention matches exactly one workspace user, a dependency refresh (zod 4, the MCP SDK to 1.32) that cleared every open Dependabot security advisory, and a new end-to-end test suite driving the built MCP server over stdio against a stubbed Linear API. **v1.2.1**, same day: the CLI's own `create`/`update` gained the same labels/state/assignee options to match the MCP tool, the search assignee filter now accepts UUIDs so "assignee" means the same thing everywhere, a CLI crash when `--labels` was omitted got fixed, and `npm run build` on Windows now goes through a Node script calling esbuild's API instead of a shell pipeline that mis-quoted arguments there. Contributors: **Jesse Vincent (staff, `obra`)** and **Ada Sen (staff)** — one commit, honoring assignee/state/UUID-assignee on create/update — plus `dependabot[bot]` version bumps.

</article>

<article class="repo">

### [prime-radiant-inc/evener](https://github.com/prime-radiant-inc/evener)

<p class="repo-desc">A coding agent: give it a prompt and it reads, writes, runs commands, and searches code in a loop until the work is done, using native tool-calling across OpenAI, Anthropic, and Google models.</p>

<RepoStat org="prime-radiant-inc" name="evener" week="2026-10-26" />

Tagged release v0.3.17, a bare version tag with GitHub's auto-generated changelog. The dominant thread this week is a large, two-track internal refactor run under branch tags `W1-*` and `W2-*` across the `agent`, `hub`, `web`, `native`, and `appwire-client` code: long functions split into named phases, leaf packages extracted (memory pages, host resources, frontmatter editors), and dozens of hand-rolled test-fixture copies replaced by a handful of shared helpers (one `connectFakeClient`/`connectReadyFakeClient` pair standing in for duplicated setup across many test files), running in parallel with a "Wave 2" documentation audit closing and ruling on review findings. Outside the refactor: host records moved to live in the operation store with `hub.toml` keeping only the host list; a provider-connection-card fast-follow; queued-message edit/remove unified across browser and native; a single-owner Retry-eligibility path shared between browser and native; small web-UI additions (a "Comic Chat" client, floating next-needs-you controls, a compact activity sidebar); and a Gemini-gateway fix retrying a model-not-found 404 on custom base URLs. Two small outside-contributed fixes also landed: a bounded command-hook-output-capture fix and a `.gitignore` trailing-slash cleanup. In-org author: **Jesse Vincent (staff, `obra`)**, plus outside contributors **`anubhavgupta121`** and **`wangyusheng1985`**, each landing a small fix, and `dependabot[bot]` version bumps.

</article>

<p class="repo-desc">A portable coding-agent plugin for shepherding GitHub pull requests through CI and review.</p>

<RepoStat org="prime-radiant-inc" name="shepherd-pr" week="2026-10-26" />

Sole author: **Jesse Vincent (staff, `obra`)**.

### [obra/model-training-journal](https://github.com/obra/model-training-journal)

<p class="repo-desc">An AI-assisted engineering journal: small-model training methods, measurements, failures, and limitations.</p>

<RepoStat org="obra" name="model-training-journal" week="2026-10-26" />

A brand-new repo, created mid-window and published to GitHub Pages: a public engineering journal for a small-model training run, built as a deterministic static site (no CDN, no remote fonts, no tracking JavaScript beyond a snapshot-age clock) with static SVG charts, explicitly excluding any raw logs, model weights, dataset copies, or credentials from the repository itself. This week's commits are its entire history so far, moving from an initial published entry through a run of numbered checkpoint updates, a plain-language-companion and evidence-dashboard addition, and a "V6 first checkpoint and run boundary" post. All of them land under an identity called "Journal automation," with no linked GitHub account. The line-count chip is hidden for this repo, because its churn is almost entirely generated checkpoint and chart files.
